# PTG-MEM

[English version](README.md)

**Хаос на диске, порядок в голове у модели.**

Локальная память для Claude Code и Codex. Держит карту всего, что лежит в папке: заметки, выгрузки
чатов, скрипты, код, который тут никто не писал. Модели отдает только нужные куски и помечает, какие
из них потом заменили.

![Запрос получает нужную память; после того как решение поменялось в документах, агент получает новую версию, а старую видит зачеркнутой](docs/demo.gif)

*Настоящие скриншоты окна PTG-MEM на демо-проекте. Решение поменялось в `docs/decisions.md`, и
следующий запрос получает текущую версию. Старая показана зачеркнутой, чтобы агент ее не брал.*

## Проблема

Рабочая папка через несколько месяцев с ИИ выглядит так: выгрузки чатов, заметки, три версии одного
плана, полуживые скрипты, модуль, который Claude написал в прошлом месяце и с тех пор его никто не
открывал. Если отдать все это модели целиком, дальше все идет по одному из трех сценариев.

* **Не влезает или съедает лимит.** Модель перечитывает кучу на каждой задаче.
* **В длинном списке модель теряется.** По моим замерам маленькая локальная модель находила первую из
  18 записей в 61 % случаев, а последнюю в 21 %
  ([отчет](https://github.com/Deadatreides/LLM-MEASUREMENTS/blob/main/experiments/theory_emergent_swarm/reports/REPORT_K1.md)).
* **Модель строит на плане, который вы отменили две недели назад.** Старая версия и новая выглядят
  одинаково убедительно, и в папке нигде не написано, какая победила.

## Что делает PTG-MEM

* **Индексирует сам.** Локальный демон следит за папкой проекта и за сессиями Claude Code и Codex.
  Новый или измененный файл находится через несколько секунд, команду «проиндексировать» больше
  запускать не нужно.
* **Подкладывает контекст к каждому запросу.** Хук добавляет 3-5 самых подходящих фрагментов, около
  тысячи токенов с жестким потолком. Если ничего достаточно близкого нет, не добавляет ничего.
* **Знает, что заменили.** Память - граф с типами связей: `supersedes`, `contradicts`, `fixes`,
  `refines`, `revises`. Когда заметка меняется, старая версия остается в истории и как текущая больше
  не выдается.
* **Показывает, что делает.** В локальном окне виден каждый запрос и что именно к нему подложено,
  плюс поиск и журнал решений.

## Код, который тут никто не писал

Легаси - такая же куча. Написал ли его коллега в 2014 году или Claude вчера, никто в комнате его не
читал. В PTG-MEM есть карта кода (Code PTG): она раскладывает кодовую базу по карточкам и отвечает на
вопросы агента через MCP.

* **Карточка на каждую функцию и класс:** параметры, вызовы наружу, размер, сложность, где лежит.
* **Кто ее использует и что использует она:** вызовы, импорты, реализации, тесты. Это статический
  анализ, без вызовов нейросети.
* **Что может сломаться, если ее поменять:** все, что дотягивается до нее по этим связям, на N шагов.
* **История версий карточки.**

Python, а также C, C++ и CUDA через tree-sitter. Пока это отдельные CLI и MCP-сервер, установка
одной командой через `ptg install` - следующим релизом.

```bash
python -m ptg_mem.code_ptg.cli index --project path/to/code --no-embeddings
python -m ptg_mem.code_ptg.cli risks SomeClass.some_method --project path/to/code
python -m ptg_mem.code_ptg.mcp_server --project path/to/code   # MCP-сервер для агента
```

Карточки, связи и риски - статический анализ, модель для них не нужна. С моделью эмбеддингов
(`--model` или переменная `CODE_PTG_MODEL`) карточки еще и группируются по смыслу. Карта лежит в
`.code_ptg/` внутри проекта.

## Быстрый старт

```bash
pip install "ptg-mem[st] @ git+https://github.com/Deadatreides/PTG-MEM.git"   # на PyPI пока нет
cd your-project
ptg init                         # покажет, сколько файлов попадет в индекс, и спросит
ptg install claude               # хуки и MCP для этого проекта (или: ptg install codex)
ptg gui                          # живое окно
```

`[st]` ставит эмбеддер на CPU или GPU через sentence-transformers. При первом запуске `ptg init` скачает модель эмбеддингов по умолчанию (Qwen3-Embedding-0.6B,
~1,2 ГБ). Подойдет и GGUF через llama.cpp: `ptg init --gguf model.gguf` (нужен
`pip install "ptg-mem[gguf] @ git+https://github.com/Deadatreides/PTG-MEM.git"`).

Есть плагин для Claude Code (`/plugin marketplace add Deadatreides/PTG-MEM`, затем
`/plugin install ptg-mem`). Пакет Python выше ему все равно нужен.

## Замерено

На настоящем архиве из 22 405 фрагментов (Windows 10, GTX 1660 SUPER 6 ГБ, Qwen3-Embedding-4B GGUF):

| | |
|---|---|
| подбор памяти к запросу, модель прогрета | **0,10-0,13 с** |
| то же с загрузкой модели | ~3 с, только первый запрос |
| загрузка хранилища | 4,2 с (было 40 с в JSON) |
| сохранение | 11 с (было ~90 с), 646 МБ (было 1,7 ГБ) |
| от нового файла до поиска | ~12 с без событий файловой системы, сразу с ними |

## Ограничения, которые мы замерили и не прячем

* **Граф не находит больше, чем обычный векторный поиск.** На нашем архиве обычный косинус находит
  70,3 %, поиск через граф 64,9 %; на LongMemEval V1 при k=10 98,3 % против 91,7 %. Поэтому поиск
  обычный, а граф отвечает на другой вопрос: заменено ли это, оспорено или исправлено и чем. Стенд -
  в [`bench/`](bench/).
* **Догадки «А заменяет Б» по тексту шумные.** На эталонном архиве 68 % таких догадок связывают
  тексты, которые друг друга не заменяют, поэтому догадка учитывается только при косинусе выше
  0,75. Ваши собственные правки точны: для них есть `revises`.
* **Точность ответов не замерена.** Другие системы памяти публикуют точность ответов по оценке
  модели, у нас - полнота поиска. Сравнивать их нельзя, и мы не сравниваем.
* **Проверено автором на Windows 10.** Тесты движка гоняются на macOS, Linux и Windows с заглушкой
  вместо эмбеддера, прогоны с настоящей моделью на macOS и Linux еще впереди.

## Приватность

* Пока вы не запустили `ptg init` в папке, ничего не индексируется.
* Веса, дампы прогонов, `node_modules`, папки систем контроля версий пропускаются по умолчанию.
* Строки, похожие на ключи (`sk-…`, `ghp_…`, `AKIA…`, JWT, приватные ключи), вычищаются до
  эмбеддинга и сохранения.
* Демон слушает только 127.0.0.1, и каждый вызов требует токена текущего запуска.

## Бесплатно и Pro

Для личного использования бесплатно навсегда (AGPL-3.0). Pro - подписанный офлайн-ключ в духе
WinRAR: поиск сразу по всем проектам, выгрузка журнала решений в Markdown, общие пакеты памяти для
команды (в работе). Компаниям, которым AGPL не подходит, - [COMMERCIAL.md](COMMERCIAL.md).

## Откуда это взялось

Я инженер-проектировщик, не программист. За полгода опытов с локальными моделями на диске скопились
тысячи чатов, заметок и скриптов, и агент раз за разом строил на решениях, которые я уже отменил.
PTG-MEM начался как лекарство от собственного бардака. Замеры, на которых он стоит, лежат в
[LLM-MEASUREMENTS](https://github.com/Deadatreides/LLM-MEASUREMENTS).
