# Спецификация: ядро PTG-MEM — полный PTG для демона

Пакет `ptgcore` заменяет `ptg_mem/engine.py` целиком. Это все операции, которые демон, хуки, MCP и окно вызывают у
движка, на одной базе: текст, переписки, код, метадерево и любые эмбеддинги. Ядро — функции над папкой базы `home`.
Тонкий класс демона (`ptg_mem/engine_full.py`) держит эмбеддеры и переводит ответы ядра в словари прежней формы.

## Что из готового, целиком или кусками

| часть | готовое |
|---|---|
| файлы папки → текст | `memshell.convert` (MarkItDown) |
| `.py` → текст | докстринги и комментарии с метками — `ptg_mem.core.ptg_py_comments.extract_py_comments_text`, язык меток из настроек |
| экспорты чатов (.json, .jsonl, .ndjson: ChatGPT, Claude, Grok, Gemini, Meta) | `ptg_mem.core.ptg_chat_exports.extract_chat_pairs` |
| текст → атомы | `memshell.atomize`: атом — абзац, Chonkie только для длинных |
| сеансы Claude Code и Codex | `ptg_mem.transcripts.parse_claude`, `parse_codex`, списки сеансов проекта, `CompactTracker` |
| какие файлы брать | `ptg_mem.filters.FileFilter` |
| секреты | `memcore.scrub` (detect-secrets + форматы поставщиков) |
| что сохранить, снять, заменить при правке | `memcore.plan_sync` |
| связи со сроком действия, как в Graphiti | `memcore.record_relation`, `memcore.current_version` |
| хранилище, векторы, полнотекст | `ptgfull.store` (LanceDB) |
| пространства, RRF, адаптер между моделями | `ptgfull.spaces`, `ptgfull.adapter` |
| граф кода | `ptgfull.code.code_graph` (codebase-memory-mcp) |
| метадерево и швы «атом ↔ код» | `ptgfull.metatree` |
| окно отбора, правило сеанса, служебный шум | `memshell.in_window`, `memshell.session_ok`, `memshell.is_noise` |
| бюджет подсказки | `memcore.select_context` |
| блок `<ptg-memory>`, сводка | `memshell.render_recall`, `memshell.render_brief` |
| лента решений | `memshell.decision_pairs` |

## Пользовательские истории

### P1. Память знает весь проект и ничего не упускает
Файлы папки, сеансы Claude Code и Codex, экспорты чатов, заметки агента попадают в базу. При правке файла меняется
только изменённый абзац. Удалённое снимается, а не стирается.

Сценарии:
1. Дано: сеанс Claude Code из двух вопросов. Когда: `prepare` и `commit`. Тогда: два атома с временем реплик и id
   сеанса, служебные реплики (`<system-reminder>`, уведомления) не стали атомами.
2. Дано: абзац файла изменён. Тогда: новый атом заменяет старый (связь `supersedes`, источник `edit`), старый — снят.
3. Дано: файл удалён. Тогда: `retract_file` снимает его атомы, база их хранит.
4. Дано: в тексте ключ API. Тогда: в базе `<secret>`, счёт вычищенного — в плане.

### P2. Подсказка к каждому запросу — своё, в бюджете
Поиск — RRF по словам и по всем пространствам, куда есть путь (замер 9: на своём корпусе слова 61,7 %, вектор
38,3 %; на LongMemEval вектор 98,3 %; RRF не проваливается ни там, ни там). Подсказка учитывает окно от лучшего,
правило текущего сеанса, служебный шум, бюджет, пометки «заменено», «противоречит», швы с кодом.

Сценарии:
1. Дано: база пуста или запрос короче 12 символов. Тогда: пустая подсказка.
2. Дано: найденный атом заменён новым. Тогда: в подсказке пометка «replaced later».
3. Дано: эмбеддера нет. Тогда: поиск по словам работает.

### P3. Решения и их судьба
`relate` записывает связь, которую заявил агент или модель. `decisions` — лента «что заменило что и что чему
противоречит». `node` — атом целиком с соседями по файлу. `graph` — эго-сеть для окна: связи и метадерево.

### P4. Код и метадерево
`index_code` строит граф кода выбранных репозиториев (codebase-memory-mcp). Сохранение (`save`) пересобирает
метадерево: дерево кода, источники текста, швы `edits`, `reads`, `mentions`. Строки инструментов сеансов (`[Edit] путь`)
считаются правками.

### P5. Любые эмбеддинги и перенос базы
`open_home` регистрирует пространство. Другая модель под тем же именем — отказ. `query_routes` говорит демону, какими
моделями закодировать запрос (своей или через адаптер). `migrate_v6` переносит живую базу формата 6 без пересчёта
векторов: атомы, их состояния, векторы, типизированные связи, обработанные файлы.

## Требования

* ФТ-001. КОГДА источник — `claude` или `codex`, СИСТЕМА ДОЛЖНА разобрать его готовым разборщиком
  `ptg_mem.transcripts`. Время атома — время реплики, сеанс — id сеанса, `source` — вид.
* ФТ-002. КОГДА источник — файл `.py`, СИСТЕМА ДОЛЖНА брать докстринги и комментарии (`extract_py_comments_text`, метки
  на языке `lang`). Для `.json`, `.jsonl`, `.ndjson` — сперва пары экспорта чата (`extract_chat_pairs`), иначе текст.
  Для прочих — `memshell.convert`. Атомы — `memshell.atomize(path, text, 1200)`, время — время правки файла.
* ФТ-003. Для любого текста атома, вопроса и ответа СИСТЕМА ДОЛЖНА вычищать секреты `memcore.scrub` до записи.
* ФТ-004. СИСТЕМА ДОЛЖНА давать id атома `memshell.digest(f"{file}\n{position}\n{at!r}\n{text}")`, отпечаток —
  `memshell.digest(text)`.
* ФТ-005. КОГДА источник принимается снова, СИСТЕМА ДОЛЖНА сверить его `memcore.plan_sync`. Новое пишется, исчезнувшее
  снимается (`status='retracted'`, `retracted_at`), пара «на месте снятого» — связь `supersedes` с источником `edit`.
* ФТ-006. СИСТЕМА ДОЛЖНА хранить связи как `memcore.types.Edge` (действует, пока `invalid_at == 0.0`). Состояние атома:
  `retracted`, иначе `superseded`, если `memcore.current_version` даёт другой атом, иначе `active`.
* ФТ-007. КОГДА приходит запрос, СИСТЕМА ДОЛЖНА искать по словам (полнотекст) и по каждому пространству, для которого
  демон дал вектор (свой или через адаптер). Слияние — `ptgfull.spaces.fuse`, k = 60. Без снятых атомов, если не
  попросили. Повторы одного отпечатка — один раз.
* ФТ-008. КОГДА собирается подсказка, СИСТЕМА ДОЛЖНА:
  * отбросить шум (`memshell.is_noise` с `AUTOMATED`);
  * отбросить реплики текущего сеанса после последнего сжатия (`memshell.session_ok`);
  * держать окно 0,12 от лучшего (`memshell.in_window`);
  * держать порог и бюджет (`memcore.select_context`, `memshell.render_recall`);
  * пометить «replaced later», «replaces an earlier version», «contradicts» / «contradicted by» и швы с кодом.
* ФТ-009. СИСТЕМА ДОЛЖНА давать сводку сеанса `memshell.render_brief`: живых атомов, заметки агента за 14 дней.
* ФТ-010. СИСТЕМА ДОЛЖНА давать ленту решений `memshell.decision_pairs`, новые сверху, закрытые связи тоже.
* ФТ-011. СИСТЕМА ДОЛЖНА давать эго-сеть атома: связи до глубины `depth`, затем рёбра метадерева, не больше `limit`
  узлов.
* ФТ-012. КОГДА `index_code`, СИСТЕМА ДОЛЖНА строить граф кода каждого репозитория. Путь файла — с именем папки
  репозитория впереди (`PTG-MEM/ptg_mem/engine.py`), чтобы швы находили его в путях сеансов.
* ФТ-013. КОГДА `save`, СИСТЕМА ДОЛЖНА пересобрать рёбра метадерева по живым атомам и графу кода и сжать таблицы.
  Перед швами строки `[Edit] путь`, `[Write] путь`, `[MultiEdit] путь`, `[NotebookEdit] путь`, `[Read] путь` из
  `Tools:` переводятся в разметку `[инструмент <вид>: путь]`, которую знает `ptgfull.metatree`.
* ФТ-014. КОГДА `migrate_v6`, СИСТЕМА ДОЛЖНА перенести базу формата 6 (`data/meta.json`, `nodes.json`, `vectors.npy`,
  `edges.json`) без пересчёта:
  * id и состояния атомов — как были;
  * векторы — в пространство `spec`, кусками;
  * связи — в `Edge` (valid_at — время нового атома, источник `v6`);
  * `processed_files` — в таблицу обработанных файлов.
* ФТ-015. КОГДА пространство с тем же именем записано с другой моделью, `open_home` ДОЛЖНА отказать (`ValueError`).
* ФТ-016. Для любых операций чтения над пустой или несуществующей базой СИСТЕМА ДОЛЖНА отвечать пустым, а не
  исключением.

## Сущности
`Source`, `Draft`, `Entry`, `Batch`, `Report`, `Link`, `Card`, `Recall`, `Side`, `Decision`, `Node`, `GNode`, `Graph`,
`Plan`, `Stats`, `Settings` — `ptgcore/types.py`. Связь — `memcore.types.Edge`. Пространство, путь запроса, находка, узел
и ребро кода — `ptgfull.types`.

## Хранилище (LanceDB, папка `home`)
* таблицы ptgfull: `atoms` (текст, полнотекстовый индекс), `vec_<пространство>`, `spaces`, `adapters`, `code_nodes`,
  `code_edges`, `edges` (метадерево);
* свои таблицы ядра:
  * `entries` — всё об атоме, кроме вектора;
  * `relations` — связи;
  * `files` — путь и время правки обработанных файлов.

## Крайние случаи
* источник исчез между планом и приёмом;
* сеанс без реплик пользователя;
* очень длинный ход агента (больше 24 инструментов — середина свёрнута разборщиком);
* сжатие контекста;
* файл без текста;
* двоичный файл;
* запрос пустой;
* эмбеддер упал;
* атом без связей;
* связь к атому, которого нет;
* пустой граф кода.

## Допущения
* Эмбеддеры держит демон (`ptg_mem/embedders.py`: GGUF через llama.cpp, sentence-transformers, выгрузка по простою).
  Ядро получает готовые векторы и говорит, какие нужны.
* Демон запускается из окружения `rev-shell/.venv`: там llama_cpp, lancedb и ядро. Системный Python не трогается.
* Хуки, HTTP демона, MCP `ptg-mem`, окно, лицензия, CLI остаются как есть и зовут движок через класс демона.
* MCP самого codebase-memory-mcp (17 инструментов) подключается отдельно и только по согласию пользователя.
* Реранкер — после замера на своих данных.

## Критерии успеха
* Проверки kit зелёные; `python -m pytest` в папке проекта проходит.
* Тесты движка `tests/test_engine3.py` проходят на классе ядра.
* Перенос store_v6: все атомы и векторы на месте, полнота поиска на замере 9 не ниже RRF 59,6 %.
