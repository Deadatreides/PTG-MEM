# Спецификация: memshell — оболочка памяти PTG-MEM 0.3

11.10.2026. Вторая часть ревизии PTG-MEM на готовых инструментах. Первая часть — ядро решений memcore
(`PTG-MEM/rev`). memshell стоит между источниками и ядром:
- файл → Markdown → атомы-абзацы;
- находки поиска → окно отбора, текущий сеанс, обвязка;
- записи → блок памяти в подсказке и сводка сеанса;
- связи → лента решений.

Хранилище LanceDB, эмбеддер и демон в memshell не входят. Их связывает переходник PTG-MEM `ptg_mem/engine3.py`:
у него состояние и многошаговая работа с хранилищем, а это в карточки не ложится.

## Пользовательские истории

**P1. Правка файла меняет в памяти ровно правленое.** Пользователь дописал предложение в абзац заметки.
- Дано: файл из десяти абзацев, правлен один. Когда файл перечитан, тогда меняется один атом, остальные остаются.
- Замер `PTG-MEM/bench/chunk_locality.py` на 106 заметках: при нарезке по абзацам меняется ровно один атом. Упаковка
  Chonkie сдвигала границы — в среднем 6 сменённых атомов, до 25.

**P1. Документ любого формата читается.** .md, .txt, HTML, .docx, .pdf, .xlsx, .pptx → Markdown через MarkItDown.
Двоичный файл не ломает приём, а даёт пустой текст.

**P1. Подсказка показывает только нужное и не раздувается.**
- Дано: лучшая находка 0.81, вторая 0.75, третья 0.60, окно 0.12. Тогда в подсказку идут первые две.
- Дано: находка из текущего сеанса, сказанная после последнего сжатия контекста. Тогда она в подсказку не идёт:
  это ещё в окне модели.
- Сообщения обвязки (`<task-notification`, `<system-reminder` …) в подсказку не идут.
- Блок памяти не длиннее бюджета символов, включая теги.

**P2. Начало сеанса и лента решений.** Сводка говорит, сколько атомов в памяти, и называет последние решения.
Лента решений показывает пары «что чем заменено» и «что чему противоречит», новые первыми, закрытые тоже.

## Требования (EARS)

- ФТ-001. КОГДА документ режется на атомы, СИСТЕМА ДОЛЖНА взять абзацы (их разделяет пустая строка), а абзац длиннее
  предела разрезать Chonkie RecursiveChunker по символам. Для любого текста все его знаки, кроме пробелов, остаются в
  атомах по порядку.
- ФТ-002. Для любого текста отпечаток атома СИСТЕМА ДОЛЖНА считать от текста со схлопнутыми пробелами: правка одних
  пробелов — тот же атом.
- ФТ-003. КОГДА выбираются находки для подсказки, СИСТЕМА ДОЛЖНА оставить только те, что не ниже порога и не дальше
  окна от лучшей.
- ФТ-004. КОГДА находка из файла текущего сеанса, СИСТЕМА ДОЛЖНА взять её, только если сказанное было до последнего
  сжатия контекста.
- ФТ-005. КОГДА текст находки начинается с метки обвязки (после метки хода), СИСТЕМА ДОЛЖНА считать его шумом.
- ФТ-006. Для любых записей и бюджета блок памяти СИСТЕМА ДОЛЖНА уложить в бюджет. Блок открывается `<ptg-memory>` и
  закрывается `</ptg-memory>`; если показать нечего — пустая строка.
- ФТ-007. Для любых данных сводку начала сеанса СИСТЕМА ДОЛЖНА уложить в предел; не влезающее убирается с конца.
- ФТ-008. КОГДА читается файл-источник, СИСТЕМА ДОЛЖНА вернуть его Markdown (MarkItDown). Неподдержанный формат — пустая
  строка. Нет файла — FileNotFoundError.
- ФТ-009. Для любых связей лента решений СИСТЕМА ДОЛЖНА дать связи видов supersedes и contradicts, новые первыми, не
  больше заданного числа.

## Сущности

Draft, Entry и постоянные тексты блока памяти — `memshell/types.py`. Hit и Edge — из `memcore.types`.

## Крайние случаи

- Пустой текст, текст из одних пробелов, переводы строк Windows (\r\n) и старого Mac (\r).
- Абзац без пробелов длиннее предела.
- Бюджет меньше шапки блока: пустая строка, а не обрезанный тег.
- Ни одной находки. Все находки ниже порога.
- Двоичный файл. Отсутствующий файл.

## Допущения

- Правка абзаца записывается связью memcore `supersedes` с `source="edit"`. Отдельный вид `revises` прежнего графа не
  нужен: заменённое снимается, связь показывает, что его заменило.
- «Открытые нити» прежней сводки брались из веток графа ptg_core, а граф ушёл из поиска (замер: плоский косинус лучше).
  Вместо них сводка показывает последние решения и заметки за две недели; выбирает их переходник.
- Тексты блока памяти — английские, как в PTG-MEM 0.2: их читают модели, а хуки уже их ждут.
- Chonkie — с правилами по умолчанию: рецепт `markdown` скачивается с HuggingFace при каждом создании разрезателя.

## Критерии успеха

- Примеры и свойства карточек зелёные: doctest, deal.cases, CrossHair (для чистых функций).
- Переходник `ptg_mem/engine3.py` на memcore + memshell + LanceDB проходит прежние тесты PTG-MEM
  (`tests/test_engine.py`; внутренности старого движка в тестах — по новому устройству).
- Поиск на LongMemEval не хуже замера 11.10: плоский косинус по реплике при k = 10 — 98,3 %.
